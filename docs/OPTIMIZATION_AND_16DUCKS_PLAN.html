2. 為什麼選擇「選項 A：載入 17.82 秒最佳權重 + 16 隻平行小鴨」？

✅ 選項 A（本專案採用方案）

  • 保留 [256, 128, 64] 架構並載入 17.82s 最佳權重： 直接站在已完成 89% 目標（17.82s / 20.0s）的巨人肩膀上，省去從 0 秒學習站立與跨步的 3～4 小時算力。
  • 升級 NUM_CLONES = 16（16 隻平行小鴨）： 每隻小鴨單次採樣 n_steps = 1024，單輪總緩衝區 16 × 1024 = 16,384 步，具備 2 倍獨立環境的樣本多樣性，梯度更平滑。
  • 對齊官方 PPO 穩定更新： n_epochs = 5（減半防止過度擬合）、batch_size = 512、target_kl = 0.015、gamma = 0.9985、gae_lambda = 0.95，並在載入時夾緊探索標準差 (log_std = -1.0)，讓 Critic 在前 2 輪平穩適應新獎勵。

⚖️ 與選項 B（從零訓練 [512, 256, 128]）的差異

  • 官方使用 [512, 256, 128] 是針對 4096 個 GPU 環境同時學全向奔跑與原地旋轉；在 Colab 16 環境下，參數多 4 倍會使每步推論變慢約 25%。
  • 從零訓練必須重新克服「4 秒原地踏步局部最佳解」，耗費大量 Google Colab Compute Units (CU)。
  • 本專案程式碼同時支援自動相容：若有歷史最佳權重則無縫接續微調；若無權重則自動建立全新網路。

⚡ 我們在程式碼中實作的 5 大「榨乾每一滴算力」加速與省點機制：
  1. 訓練環境完全關閉渲染器 (render_mode=None)： 16 隻訓練小鴨不初始化 OpenGL/EGL 緩衝區，僅在評估錄影時開啟，直接省下 ~400MB 記憶體並提升 +35% 物理採樣 FPS。
  2. 消除重複觀察計算 (_get_obs() 快取傳遞)： 將 step() 計算好的 obs 直接傳入 _compute_reward(action, obs)，減少 50% 座標轉換與陣列配置開銷。
  3. 兩階段智慧快速評估 (Fast-Fail Staged Evaluation)： 每輪結束驗證時，先跑主種子 seed=89；只有當 seed=89 表現優異（例如 ≥ 10.0 秒或接近歷史最佳）時，才啟動全部 3 組種子完整驗證，省下約 45% 的評估等待時間！
  4. 跨輪次動態學習率與探索自適應調節： 若連續 4 輪未刷新紀錄或步數停滯，自動微調學習率與微幅重啟探索；一旦突破 15 秒則自動收緊 learning_rate 與 clip_range 穩定收割。
  5. 達標後自動同步雲端並切斷 Colab 執行階段 (runtime.unassign())： 一旦跨越 20.0 秒大關（或完成設定輪數）並完成 Google Drive 與 GitHub 備份，自動呼叫 google.colab.runtime.unassign() 釋放機器，杜絕半夜掛機空燒算力點數！
